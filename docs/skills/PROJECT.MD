# Bistro PH (`bistro_ph`) — Project Profile

## What This Is

A restaurant website built as a freelancer portfolio demo. Working brand name: **Bistro PH** (easy to rename — single-source it in one place).

- Repo name: `bistro_ph` — `ph` because menu prices are in **PHP**.
- The target is a live URL a potential client can browse today, showing the full customer flow: browse menu → add to cart → checkout → submit order.
- This is self-initiated work, **not** a commissioned project for a real restaurant. The deployed site's visitor-facing copy deliberately carries **no** fictional/demo disclosure — the owner removed it so the site reads as a real restaurant. Do not re-add one; keep only the residual truthfulness invariants (never invent a phone number, never claim an order was sent, never imply online payment, keep `robots: index: false`).

## Hard Invariants

These are truthfulness and safety rules, not style preferences. Breaking one breaks the demo's credibility with the client.

1. **Never invent a real WhatsApp/phone number.** Read it from `NEXT_PUBLIC_RESTAURANT_WHATSAPP_NUMBER`. Unset → demo mode with copy-to-clipboard.
2. **Never claim an order was persisted or sent when it was not.** The WhatsApp handoff only *opens* a draft — the user must press send.
3. **Never claim deployment succeeded** unless it actually ran and the URL was opened.
4. **Never collect payment card details** or imply online payment works without a real provider.
5. **No dead buttons, fake links, or broken image URLs.** Provide an image fallback path.
6. **Never commit `.env.local`, tokens, or service-role keys.**
7. **No database.** No Postgres, Supabase, Prisma, no `app/api/orders` route, no server-side order storage. Order data lives only in the WhatsApp message and browser `localStorage`. A browser-local order history is a demo convenience, never presented as proof the restaurant received the order.
